Image Text Extraction & Merge Skill

1. Skill Name

image-text-extraction-merge

2. Purpose

用于从一张或多张包含中文文字的图片中提取文字，并将多张图片中的内容进行：

* OCR文字识别
* 内容清洗
* 重复内容检测
* 跨图片去重
* 断句与段落恢复
* 内容排序
* 上下文合并
* 最终文案整理

目标是将用户提供的多张截图、海报、聊天记录、长图或社交媒体图片中的文字，整理成一份连续、完整、无明显重复、可以直接复制使用的中文文本。

⸻

3. Trigger Conditions

当用户出现以下需求时触发：

图片文字提取

* “帮我提取图片里的文字”
* “把图片里的字复制出来”
* “OCR一下”
* “提取图片文字”
* “把这几张图的文字整理出来”

多图片合并

* “把这几张图合起来”
* “合并一下这些文字”
* “多张图片里的内容整理成一篇”
* “去掉重复的部分”
* “帮我把截图里的内容合并”
* “按照顺序整理”
* “把这些图片里的文案整合起来”

社交媒体内容整理

尤其适用于：

* 小红书截图
* 微信聊天截图
* 微博截图
* Instagram / TikTok / Facebook截图
* 海报
* 宣传图
* 教程图片
* 长截图
* 多页笔记
* PPT截图
* 知识卡片

⸻

4. Core Workflow

整个处理流程分为八个阶段。

Step 1 — Identify Images

首先识别用户提供的全部图片，并按照：

1. 用户上传顺序
2. 图片中的页码
3. 图片中的标题或章节编号
4. 内容逻辑

确定图片的先后顺序。

如果图片本身存在明确页码，例如：

1/5
2/5
3/5

优先按照页码排序。

如果没有页码，则默认按照用户上传顺序。

⸻

Step 2 — Extract Text

逐张图片提取文字。

必须尽可能保留：

* 标题
* 副标题
* 正文
* 列表
* 编号
* 标点
* 引号
* 括号
* emoji
* 特殊符号
* URL
* 英文
* 数字
* 日期
* 人名
* 地名
* 专有名词

对于无法确认的文字，不得凭空编造。

可以根据上下文进行合理修正，但如果存在明显不确定性，应标记：

【疑似：XXX】

⸻

5. OCR Cleaning

OCR完成后进行文本清洗。

5.1 修复常见OCR错误

例如：

* “的”与“地”混淆
* “在”与“再”混淆
* “己”与“已”混淆
* “人”与“入”混淆
* “0”与“O”混淆
* “1”与“I”混淆
* 中文标点被识别成英文标点
* 断行导致的错误分词
* 重复识别字符
* 图片水印被误识别

根据上下文修正明显错误。

⸻

5.2 恢复句子

图片中的文字可能因为排版产生：

我们需要
做的第一件事情
是确认目标。

应恢复为：

我们需要做的第一件事情，是确认目标。

但不得改变原文实际含义。

⸻

5.3 保留原始表达

不要在OCR阶段擅自：

* 改写观点
* 添加解释
* 美化文案
* 改变语气
* 增加不存在的信息

OCR阶段的核心目标是：

准确恢复原始文字。

⸻

6. Duplicate Detection

多张图片之间可能存在大量重复内容。

例如：

图片1

德国音乐学院申请需要提前准备。

图片2

德国音乐学院申请需要提前准备。
首先要确定目标学校。

最终应保留：

德国音乐学院申请需要提前准备。
首先要确定目标学校。

而不是：

德国音乐学院申请需要提前准备。
德国音乐学院申请需要提前准备。
首先要确定目标学校。

⸻

7. Duplicate Types

重复检测需要处理以下几种情况。

7.1 完全重复

两个图片出现完全相同的句子。

→ 只保留一次。

⸻

7.2 部分重复

例如：

图片1：

德国音乐学院申请需要提前准备。
首先要确定目标学校。

图片2：

首先要确定目标学校。
然后确认考试要求。

最终：

德国音乐学院申请需要提前准备。
首先要确定目标学校。
然后确认考试要求。

⸻

7.3 重叠段落

例如：

图片1：

选学校的时候，需要考虑教授、城市和专业方向。

图片2：

需要考虑教授、城市和专业方向。除此之外，还要考虑考试要求。

最终：

选学校的时候，需要考虑教授、城市和专业方向。除此之外，还要考虑考试要求。

⸻

7.4 同义重复

如果只是表达方式相似，但不是明显重复，不要自动删除。

例如：

提前确认考试要求。

以及：

在报名之前，最好先查看学校官网的考试要求。

虽然意思接近，但可能属于不同信息。

除非能够确定是同一段内容，否则保留。

⸻

8. Contextual Merge

去重之后，需要将不同图片中的内容按照逻辑合并。

优先级：

1. 明确页码
2. 原始上传顺序
3. 标题结构
4. 内容衔接
5. 上下文逻辑

例如：

图片1：

一、选择学校

图片2：

二、准备曲目

图片3：

三、准备语言

最终：

一、选择学校
……

二、准备曲目
……

三、准备语言
……

⸻

9. Preserve Structure

如果原图片具有明显结构，应尽量保留。

例如：

原图

德国音乐学院申请

1. 选学校
2. 选教授
3. 准备曲目
4. 准备语言

最终仍应保持：

德国音乐学院申请

1. 选学校
2. 选教授
3. 准备曲目
4. 准备语言

不要将结构全部变成普通段落。

⸻

10. Handling Social Media Screenshots

对于小红书、微博、朋友圈等截图，需要区分：

主体内容

例如：

* 标题
* 正文
* 图片文字
* 作者观点
* 列表
* 标签

UI元素

通常不需要提取：

* 点赞
* 收藏
* 评论数量
* 分享按钮
* 返回按钮
* 时间
* 电量
* 网络状态
* 导航栏
* 无意义用户名

除非用户明确要求完整提取。

⸻

11. Handling Repeated Header / Footer

如果每张图片都存在相同的：

@用户名
德国留学分享

或者：

第1页 / 共8页

这类页眉页脚：

* 如果属于正文内容 → 保留
* 如果明显只是界面元素 → 删除
* 如果不确定 → 默认保留一次

⸻

12. Formatting Rules

最终输出应：

* 使用简体中文
* 保留原文语气
* 保留原文结构
* 修正明显OCR错误
* 删除明确重复内容
* 合并被图片切断的句子
* 不随意扩写
* 不改变原意

默认使用：

标题
正文第一段。
正文第二段。
1. 第一项
2. 第二项
3. 第三项

⸻

13. What NOT To Do

除非用户明确要求，不得：

不得擅自改写

不要把：

我觉得这个方法比较适合新手。

改成：

对于新手来说，我强烈推荐这个方法。

⸻

不得擅自总结

用户要求“提取并合并”时，不要直接变成摘要。

⸻

不得删除非重复信息

即使内容看起来不重要，也不要因为个人判断而删除。

⸻

不得补充网络信息

图片中没有的信息，不应通过互联网自动补充。

⸻

不得改变观点

尤其是：

* 个人观点
* 政治观点
* 产品评价
* 学校评价
* 教授评价
* 留学建议

必须保持原始表达。

⸻

14. Output Modes

根据用户要求，可以提供以下模式。

Mode A — 原文提取

只提取文字，不修改内容。

⸻

Mode B — 清洗版

修正明显OCR错误，并恢复正常段落。

⸻

Mode C — 合并去重版

多张图片：

提取 → 清洗 → 排序 → 去重 → 合并

这是默认模式。

⸻

Mode D — 发布版

在用户明确要求“整理成小红书文案 / 发布文案 / 可直接使用”时：

提取 → 清洗 → 去重 → 合并 → 轻度润色 → 发布格式

此模式允许进行语言优化，但不得改变原文核心观点。

⸻

15. Multiple Image Processing Algorithm

对于 N 张图片：

Images
  ↓
Image ordering
  ↓
OCR extraction
  ↓
Text cleaning
  ↓
Paragraph reconstruction
  ↓
Cross-image duplicate detection
  ↓
Overlap detection
  ↓
Contextual merging
  ↓
Structure restoration
  ↓
Final proofreading
  ↓
Output

⸻

16. Duplicate Removal Priority

去重时按照以下优先级：

完全重复
    ↓
连续重复
    ↓
段落重叠
    ↓
句子重叠
    ↓
明显OCR重复

对于仅仅“意思相近”的内容：

默认不删除。

⸻

17. Conflict Handling

如果不同图片中的文字存在冲突：

例如：

图片1：

需要准备B2德语。

图片2：

不需要B2德语。

不要自行判断哪个正确。

输出：

【内容存在差异】

图片1：需要准备B2德语。
图片2：不需要B2德语。

如果用户要求，可以进一步帮助分析。

⸻

18. Missing Text

如果图片中的文字无法识别：

使用：

【无法识别】

或者：

【疑似：XXXX】

不要编造缺失内容。

⸻

19. Final Quality Check

输出前检查：

OCR

* [ ]	是否存在明显错字？
* [ ]	是否漏掉标题？
* [ ]	是否漏掉列表？
* [ ]	数字是否正确？
* [ ]	英文是否正确？

Merge

* [ ]	是否删除完全重复？
* [ ]	是否处理跨图片重叠？
* [ ]	是否保留不同信息？
* [ ]	是否按照正确顺序？

Formatting

* [ ]	段落是否完整？
* [ ]	标题是否清晰？
* [ ]	编号是否连续？
* [ ]	标点是否正常？

Fidelity

* [ ]	是否改变原意？
* [ ]	是否擅自添加内容？
* [ ]	是否进行了未经要求的总结？

⸻

20. Default Response

当用户上传多张图片但没有明确说明处理方式时，默认执行：

提取全部中文文字 → 清洗OCR错误 → 按图片顺序排列 → 删除重复内容 → 合并重叠段落 → 输出完整整理版。

不需要反复询问用户。

默认输出：

以下是将图片中的文字提取、去重并合并后的完整版本：
【整理后的内容】
……

⸻

用户上传三张图片。

图片1：

图片2：

第一件事是确定学校。
第二件事是联系教授。

图片3：

第二件事是联系教授。
第三件事是准备语言。

最终：

德国留学准备

第一件事是确定学校。

第二件事是联系教授。

第三件事是准备语言。

⸻

22. Principle

本 Skill 的核心原则：

Extract first. Clean second. Deduplicate third. Merge fourth. Rewrite only when explicitly requested.

即：

先提取，后清洗；先去重，再合并；未经用户要求，不擅自改写。
